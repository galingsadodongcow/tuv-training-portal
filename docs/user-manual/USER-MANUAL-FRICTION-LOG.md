# User-Manual Friction Log — Academy Portal

> Instances where **documenting the workflow was complicated because the workflow itself is complicated.** The manual documents the *correct* current behaviour; this log records where the application should change so the manual can get simpler. Severity: Critical / High / Medium / Low. Cross-referenced to the UX Audit where applicable.

| ID | Role | Workflow | Screen | Observed problem | Why users struggle | Steps now → ideal | Suggested improvement | Severity |
|---|---|---|---|---|---|---|---|---|
| **FR-DUP-1** | Sales | Lead capture | New inquiry | No lookup against existing customers; company/contact/email re-typed | Same customer logged twice; downstream duplicate orders | ~4 fields typed → 1 (pick existing) | Company field = typeahead over customers + prior inquiries; link and inherit | **High** |
| **FR-HANDOFF-1** | Coordinator→Ops | Endorsement | Order detail | Endorsing moves the order to Ops' queue but sends **no notification**; ownership transfer is implied, not shown | Ops must watch the queue; urgent orders slip; "who owns it now?" is unclear | queue-watching → push notification + explicit owner line | Notify/queue-task the receiver on endorse & return; show "Now with Operations · awaiting acceptance" | **High** |
| **FR-STATUS-1** | All | Reading an order | Order detail, lists | Three status fields (fulfilment stage, order status, collection) + health, on one record | Users mentally combine independent systems; new hires can't decode "For Order Creation" | decode 3 systems → read one labelled line | Render `Stage · Health · Collection` as one labelled line everywhere; human-phrase the stage enums | **High** |
| **FR-SORT-1** | Ops/Coord | Find in a table | Orders | Column sort reorders only the current 50 rows but looks global | Users trust a sort that lied; miss records | page-local → server-side sort | Push sort into the paged query | **High** |
| **FR-VIEWS-1** | All operational | Daily triage | Orders, Calendar, Queue | No saved views; the same filter is rebuilt every session | Repeated setup; inconsistent triage between people | rebuild filters daily → 1 click a saved view | Ship the existing `useSavedViews` hook with role defaults | **High** |
| **FR-VALID-1** | All creators | Any create form | Inquiry, Quote, Course, Session | Only the order form shows inline field errors; others fail on Save with a toast | Users don't know which field is wrong until after they submit | trial-and-error → inline errors on blur | Generalise the order form's inline-error pattern to all forms | Medium |
| **FR-CONFIRM-1** | Ops | Confirm a session | Session detail | Two confirmation paths (raw status override vs Confirm Go) can diverge | Which button is "right"? Audit trail splits | two doors → one (Confirm Go) | Make Go/No-Go the only confirm path; demote raw override to a reason-gated correction | Medium |
| **FR-REASON-1** | BO/Ops | Governance/irreversible | Approvals, No-Go, Merge, Participant remove | Reason optional on several irreversible/governance actions (only e-learning "grant anyway" and return/override enforce it) | Weak audit trail; rejections without rationale | optional → required note | Require a note on merge, no-go, and approval rejections (reuse the reason arg) | Medium |
| **FR-PAY-1** | Ops/BO | Trust the money | Order header | `payment_status` can read "Paid" with a non-zero AR balance | Users can't trust the header pill | inconsistent → reconciled | Derive/lock `payment_status` from the AR ledger | Medium |
| **FR-EDIT-1** | Sales/Coord | Fix customer data | Customer 360 | Overview core fields are read-only for everyone (no edit surface) | Wrong email/phone can't be corrected in place | no edit → inline edit | Add a customer core-field edit surface | Medium |
| **FR-SEARCH-1** | Auditor/All | Find a record | Search | Exact match only; no typo tolerance, no recent searches, no preview; training search ranks past sessions first | Slow reconstruction; misses on a typo | multiple tries → forgiving search + preview | pg_trgm fuzzy match; result preview; recent searches; fix session ordering | Medium |
| **FR-RETURN-1** | Coord/Ops | Return an order | Order detail | The return dialog labels the reason "required" but the component is passed "optional" (a late guard catches empty) | Confusing/late error | mismatch → consistent required | Pass `reason:'required'` to the dialog | Low |
| **FR-TOAST-1** | Ops | Assessment entry | Roster panel | Score/result saves with no success toast (the only silent action) | Users re-check whether it saved | silent → confirmation | Add a success toast | Low |
| **FR-NOTIF-1** | All | Notifications | Notification center | Flat time-list; no priority/grouping/type; some deep-link to a list not the record | "Is this mine to act on?" needs reading each one | scan all → scan "Needs action" | Split action vs FYI; add priority + record deep-links | Medium |
| **FR-MYWORK-1** | All | Triage | My Work | Tasks/approvals/exceptions/duplicates look alike; three colour vocabularies in one scroll | Can't tell task from FYI at a glance | read each row → scan by stripe/verb | Per-type left severity stripe + a verb (Do/Decide/Review/Resolve); unify to the health scale | Medium |
| **FR-CAL-1** | Ops | Share a session view | Calendar | The session drawer state isn't in the URL | Can't share the exact drawer link | open full record → deep-linkable drawer | Put drawer state in the URL | Low |
| **FR-MOBILE-1** | Ops | Phone use | Calendar, buttons | Fill/Go columns hidden on mobile; touch targets below 44px | Hard to check a session on a phone | — | Keep Fill/Go on mobile; 44px targets | Low |
| **FR-CONTACT-1** | Coord | Remove a contact | Contacts panel | Contacts hard-delete (inconsistent with soft-delete everywhere else) | Irreversible; contradicts the mental model | hard delete → soft (status) | Add `contact.status` + `fn_remove_contact` | Medium |

## Summary
- **Critical:** 0 (no workflow is broken or blocked).
- **High:** 5 — duplicate customers, silent handoff, status sprawl, misleading sort, no saved views.
- **Medium:** 9 · **Low:** 4.

The recurring root causes behind most rows: (1) tables aren't operable working surfaces, (2) forms don't validate inline or prevent duplicates, (3) process status vs health isn't split visually, (4) the Coordinator→Operations handoff is silent. Fixing those four collapses most of this log.
